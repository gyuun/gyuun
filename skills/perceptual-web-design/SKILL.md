# Perceptual Web Design

웹 화면을 컴포넌트의 집합이 아니라 사용자가 정보를 이해하고 행동하는 순서로 설계한다. 특정 미감이나 프레임워크를 강제하지 말고 사용자가 선택한 스타일과 기존 디자인 시스템 안에서 아래 원칙을 적용한다.

## 작업 방식

- 기존 화면·코드·디자인 토큰을 먼저 확인하고, 사용자의 주요 과업과 가장 먼저 읽혀야 할 정보를 파악한다. 좁은 수정 요청을 전체 리디자인으로 확대하지 않는다.
- 구현 요청이면 실제 코드를 수정한다. 리뷰 요청이면 관찰한 문제, 사용자에게 미치는 영향, 구체적인 개선안을 중요도순으로 제시한다.
- 사용자의 목표에 가장 큰 영향을 주는 위계와 배치부터 조정하고, 색상·장식·모션은 이를 보조하도록 사용한다.
- 변경 범위에 맞게 실제 렌더링과 상호작용을 확인한다. 브라우저나 실행 환경을 사용할 수 없으면 확인하지 못한 항목을 명시한다.

## 지각적 디자인 원칙

### 읽는 순서를 설계한다

주요 정보 → 보조 정보 → 세부 정보의 흐름을 만든다. 제목, 핵심 내용, 주요 행동의 관계가 자연스럽게 드러나게 한다. 시각적 배치와 DOM의 의미적 읽기 순서, 키보드 탐색 순서가 어긋나지 않게 한다.

### 강조에는 예산이 있다

크기·굵기·색상·대비·모션을 모든 요소에 동시에 쓰지 않는다. 서로 경쟁하는 강조를 줄이고 실제로 중요한 요소에 집중한다. 보조 정보를 약하게 표현하더라도 읽기 어려운 대비나 글자 크기로 낮추지 않는다.

### 여백으로 관계를 전달한다

관련 요소는 가깝게, 서로 다른 그룹은 더 멀게 배치한다. 테두리·카드·구분선을 추가하기 전에 근접성과 정렬로 관계를 표현할 수 있는지 검토한다. 입력 필드, 상호작용 영역, 밀도 높은 표처럼 경계가 이해를 돕는 경우에는 명확한 경계를 유지한다.

### 보이지 않는 구조를 만든다

공통 정렬선, 간격 척도, 타이포그래피 척도, 그리드 규칙을 사용한다. 기존 토큰이 있으면 재사용하고 임의의 수치를 반복해서 추가하지 않는다. 광학적 보정이 필요하면 의도적으로 예외를 두되 주변 요소와의 관계를 확인한다.

### 시각적 무게를 의미적 중요도에 맞춘다

장식이나 부가 정보가 핵심 내용·주요 행동보다 두드러지지 않게 한다. 오류, 경고, 작업 진행 상태도 현재 과업에 미치는 영향에 맞게 강조한다. 시각적 단순함을 위해 필수 안내를 숨기지 않는다.

### 중요한 정보는 색상 외의 단서로도 전달한다

오류·성공·선택 상태 등을 색상만으로 구분하지 않는다. 텍스트 레이블, 형태, 아이콘, 패턴 등 적절한 단서를 함께 제공한다. 위치나 아이콘만으로 의미가 충분히 전달된다고 가정하지 않는다. 아이콘만 있는 컨트롤에는 접근 가능한 이름을 제공한다.

### 색상을 정보의 의미에 맞게 사용한다

일반 UI에서는 브랜드와 기존 상태 색상의 의미를 일관되게 유지한다. 데이터 시각화가 있을 때 다음 기준을 적용한다.

- 순서가 있는 크기·강도: 순차형 팔레트.
- 의미 있는 기준점의 양쪽 편차: 발산형 팔레트.
- 순서가 없는 범주: 범주형 팔레트.

정량 시각화에서는 지각적으로 균일한 팔레트를 우선 검토한다. 실제로 의미 있는 기준점이 없으면 발산형 팔레트를 억지로 적용하지 않는다. 레이블이나 범례를 함께 제공한다.

### 제약이 있는 환경에서도 핵심을 이해할 수 있게 한다

- 작은 뷰포트, 확대된 텍스트, 긴 콘텐츠에서도 정보 순서와 주요 행동을 유지한다.
- 색각 차이와 시각 효과 미지원 상황에서도 텍스트와 구조로 의미를 전달한다.
- 모션 감소 설정을 존중하고, 애니메이션이 없어도 상태를 이해할 수 있게 한다.
- 네트워크·스크립트 실패 시 영향을 받은 작업을 명확히 실패로 표시한다. 오류를 빈 결과·가짜 데이터·성공 상태로 바꾸거나 조용히 다른 실행 경로로 전환하지 않는다.
- 기존에 표시된 정보를 유지하는 경우 최신 정보나 성공 결과로 오해되지 않게 상태를 명시한다. 스크립트가 필수인 기능을 작동하는 것처럼 표현하지 않는다.
- 정적 콘텐츠의 가독성을 유지하되, 이 원칙만을 이유로 별도 무스크립트 구현이나 아키텍처 변경을 추가하지 않는다.

## 변경 후 확인

수정한 화면에 해당하는 항목만 검증한다.

- 첫 시선이 핵심 정보와 주요 행동으로 이어지는가?
- 정렬과 간격이 그룹 관계를 명확히 전달하는가?
- 작은 화면과 텍스트 확대에서도 내용이 잘리거나 주요 행동이 가려지지 않는가?
- 키보드 접근과 포커스 표시가 유지되며, 중요한 상태에 색상 외의 단서가 있는가?
- 변경한 비동기 UI의 로딩·실제 빈 결과·오류가 서로 구분되는가?

완료 시 핵심 변경과 그 이유, 실제 수행한 검증, 확인하지 못한 부분을 간결하게 보고한다. 스크린샷만 보고 상호작용이나 접근성 검증을 완료했다고 주장하지 않는다.
